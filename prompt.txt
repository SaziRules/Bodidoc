Bodidoc Dark Mode Implementation

You are working inside the existing **Bodidoc Next.js production codebase**.

Your task is to implement a complete, production-grade **dark mode for the entire website**.

Approach this as a **Senior UX/UI Developer with 10+ years of production experience**, working on an established website where regression prevention, visual fidelity, accessibility, maintainability, and restraint are more important than rewriting code.

## PRIMARY OBJECTIVE

Implement a polished dark mode across the entire Bodidoc website, controlled by a **moon/sun theme toggle placed inside the existing header announcement bar**.

The existing website is the source of truth.

**Do not redesign Bodidoc.**

Dark mode must feel like the existing Bodidoc design system translated professionally into a dark environment.

The implementation must introduce **no breaking changes**.

When light mode is active, the website must remain visually and functionally identical to its current state.

# IMPLEMENTATION PHILOSOPHY

Do not solve dark mode by scattering hundreds of arbitrary declarations such as:

`dark:bg-[#111111]`

throughout the application.

Instead, establish a small, coherent semantic theme system.

Think in roles such as:

* page background
* surface
* elevated surface
* foreground
* body text
* secondary text
* muted text
* border
* strong border
* input
* brand
* accent
* text-on-brand

Then map existing components onto those semantic roles.

Use component-specific dark overrides only where the design genuinely requires them.

---

# CRITICAL: DO NOT BLINDLY REPLACE COLORS

The same hexadecimal colour may represent different semantic roles.

For example, `#112942` may currently represent:

* primary heading text
* button background
* Bodidoc branding
* decorative accent
* icon colour
* navigation colour
* border
* header background

Those are **not equivalent**.

Do not globally replace every occurrence of `#112942`.

Classify colours according to their **purpose within the component**.

Brand colours that remain appropriate in dark mode should remain brand colours.

The goal is not:

> replace light colours with dark colours.

The goal is:

> translate the existing visual hierarchy into a dark theme while preserving Bodidoc's identity.

# THEME TOGGLE

* moon icon for switching to dark mode
* sun icon for switching to light mode

The icon control should be elegant and restrained.

It must work correctly across the announcement bar's responsive states.

Preserve all existing announcement-bar content and functionality.

Do not shift or break existing header alignment.

* focus-visible state
* keyboard accessibility
* pointer target
* ARIA labelling

# THEME PERSISTENCE

Use a robust production-grade approach such as `next-themes` if it integrates safely with the current architecture.

The user's theme selection must persist between:

* route changes
* refreshes
* sessions
